# 2026-10-22: Project scaffold

## Context

Phase 1 needs a static one-page site on Vercel within 48 hours, using the stack fixed in CLAUDE.md.

## Decisions

- **Static output, no Vercel adapter.** Astro's default static build is all Vercel needs. An adapter only becomes necessary when we add a server function (for example, the enquiry backend in a later phase).
- **Site URL from Vercel.** `astro.config.mjs` sets `site` from `VERCEL_PROJECT_PRODUCTION_URL` so canonical and Open Graph URLs are absolute before a domain exists. Swap in the real domain once it's known (Open Question 7).
- **Generated brand icons.** The logo PNG sits on pure white, which the brand forbids, so `scripts/brand-icons.mjs` turns the white into transparency and recolours the crest in Ink. It then writes the favicon (AM monogram only, for legibility at 32px), touch icons and a 1200×630 OG image on Warm Linen into `public/`. It uses `sharp`, which Astro already depends on, so no new dependency. Re-run it when an SVG logo arrives. Once the hero photo is approved, the OG image may switch to it.
- **Fonts.** Cinzel 400/500 and Cormorant Garamond 500, 500 italic and 600, all self-hosted via `@fontsource`. Body text is set at 500 because Cormorant 400 is spindly on screen.
- **Section list as data.** Section ids and nav labels live in `src/data/content.ts`. The header and the stubs are generated from it, and a unit test checks the ids are unique and URL-safe.
- **Header navigation.** Five links plus Enquire. On phones and tablets (below 72rem) the links sit behind a Menu button, which closes on Escape or after a link is chosen. Without JavaScript the links show inline and wrap.

## Consequences

- Section stubs (`SectionStub.astro`) are temporary and are replaced one by one in session 3.
- `astro.config.mjs` isn't type-checked (no `@types/node`).
